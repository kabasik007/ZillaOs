# Zilla Notepad — перший редагований документ в ZillaOS

## Стан

Застосунок **Zilla Notepad** створено як п'ятий вбудований view;
він користується тим самим `ApplicationManager`, що Start, Dock і App Center.
Це ще **не ізольований user-space процес**, а окремий no_std модуль
стану редактора в ранньому Rust-ядрі.

Текст можна набирати, змінювати, створювати нові `.TXT` документи,
зберігати їх у bounded RAMFS і відкривати з Files.

```text
Desktop / Start / App Center / F10
               |
          ApplicationManager
               |
         Zilla Notepad view
               |
         apps/notepad.rs
               |
      fs/ramfs.rs (volatile)
               |
       Users / Guest / Documents
```

## Керування

1. **Відкрити:** вибрати Notepad у Start, App Center або Dock.
   У ZillaOS усі вбудовані програми мають одну систему запуску.
2. **Друкувати:** текст через фізичну клавіатуру VMware; підтримуються
   ASCII символи, пробіл, цифри, основна пунктуація, Shift.
3. **Редагувати:** Backspace видаляє попередній символ, Enter додає
   новий рядок; стрілки ліворуч/праворуч пересувають курсор.
4. **Зберегти:** натиснути **SAVE** на панелі редактора або `F11`,
   або `Ctrl+S`. Початковий файл зветься `NOTE01.TXT`.
5. **Новий документ:** кнопка **NEW** або `F12`. Назва наступного
   документа — `NOTE02.TXT`, потім `NOTE03.TXT` тощо.
   Якщо є незбережені зміни, програма спершу просить зберегти їх.
6. **Переглянути файли:** кнопка **DOCUMENTS** у Notepad або Files →
   Users → Guest → Documents. Збережений `NOTE01.TXT` з'явиться поруч
   із вбудованим `WELCOME.TXT`. Клік на записаному файлі відкриває
   його у Notepad для подальшого редагування.

## Гарантії та обмеження

- **Жодного запису на диск.** Файли розміщені тільки в оперативній
  пам'яті, зникають після перезавантаження VM, навіть якщо видно
  повідомлення "SAVED IN RAMFS".
- До **8 текстових файлів** по **512 байтів** кожен у RAMFS. Більший
  текст відхиляється; переповнення не псує вже збережені файли.
- Поки підтримуються **ASCII та US PS/2** для введення. Мова меню
  UA/EN/RU не означає підтримку кириличної клавіатури в редакторі.
  UTF-8, розкладки й IME потребують окремої системи вводу.
- Застосунок використовує простий моноширинний bitmap-font,
  який зараз відображає літери великими. При цьому вміст у RAMFS
  зберігає байти введення з урахуванням Shift.
- Можна редагувати текст із середини рядка за допомогою лівої/правої
  стрілок. Це не повноцінний текстовий редактор з виділенням,
  Undo/Redo або системним буфером обміну.
- Усі дії обмежені гостьовим `/Users/Guest/Documents`;
  немає відкриття файлів Windows `C:` або VMware хостової системи.
- Після переходу на writable VFS і блочний драйвер потрібно
  замінити RAMFS через незалежний `StorageService`, не переписуючи
  логіку інтерфейсу Notepad.

## Архітектурні модулі

- `src/apps/notepad.rs` — редактор, курсор, перевірка символів,
  512-байтовий буфер, статус збереження, без I/O портів.
- `src/apps/notepad_ui.rs` — спільні клікабельні зони NEW/SAVE/DOCUMENTS.
- `src/fs/ramfs.rs` — віртуальні імена .TXT, bounded in-RAM слоти,
  атомарна заміна вмісту, відмова від небезпечних шляхів.
- `src/shell/desktop.rs` — PS/2 клавіатурні події, фокус, маршрутизація.
- `src/services/app_manager.rs` — відкриття/відновлення Notepad як
  зареєстрованого вбудованого застосунку.
- `src/graphics.rs` — поточний GUI renderer (виділятимемо з нього
  окремі app-renderer модулі після запуску native user-space процесів).

## Порядок перевірки у VMware

```powershell
cd M:\projects\ZillaOs
git pull origin main
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows.ps1 -Action BuildRun
```

Після запуску: Start → Notepad → написати `Hello ZillaOS` →
`Ctrl+S` → Documents → відкрити `NOTE01.TXT` → дописати рядок →
знову зберегти → переконатися, що текст змінився.

**Автоматичні перевірки**: тести editing/cursor/bounds, RAMFS
захисту, відкриття з Files, GUI geometry, компіляція
`x86_64-unknown-none` у GitHub CI.

[FILESYSTEM.md](FILESYSTEM.md).
