# ZillaOS Desktop — робоча оболонка (листопад 2026)

## Що вже працює

У VMware Workstation перевірено завантаження Rust x86-64 ядра через
Limine UEFI, графічний RGB32 framebuffer, курсор PS/2 та керування
вікнами. На цій основі створено першу функціональну оболонку Desktop.
Модулі filesystem/source-layout пройшли GitHub CI; графічна навігація
папками цієї нової редакції потребує окремого тесту у VMware.

**Керування**

- F1 — меню Start, F2 — Files, F3 — Terminal, F4 — Settings, **F10 — App Center**.
- **Zilla Notepad:** F11 / Ctrl+S — зберегти, F12 — новий документ; Enter — новий рядок, Backspace — видалити символ. Документи в RAMFS доступні через Files. [Інструкція](NOTEPAD.md).
- F5 — темна/світла тема без перезавантаження.
- F6/F7 — згорнути/розгорнути активне вікно.
- F8 — змінити мову інтерфейсу: українська → English → русский.
- F9 — показати робочий стіл (згорнути всі вікна), повторно відкрити
  вікно через Dock або ярлик на столі.
- Tab — перейти до іншого вікна; Esc — закрити або сховати меню.
- Стрілки пересувають вікно, Shift+стрілки змінюють його розмір.
- Мишкою можна перетягувати вікна, користуватися червоною/жовтою/зеленою
  кнопками в заголовках, Dock, ярликами, верхнім меню та Settings.

**Application Framework v0 (новий)**

Додано четверту вбудовану програму **Zilla App Center** та п'яту — **Zilla Notepad**. App Center показує всі п'ять зареєстрованих програм і дозволяє відкривати їх кліком. Start, Dock, ярлики та App Center беруть програмні дані з
одного реєстру `src/apps/mod.rs` і направляють запуск через
`src/services/app_manager.rs`. Менеджер вікон залишається єдиним
власником стану відкриття/фокусу. Це **вбудовані views ядра, не
ізольовані виконувані програми**. Подробиці: [APPLICATIONS.md](APPLICATIONS.md).

**Нові елементи Desktop (після оновлення ISO)**

- Зліва кнопка Z / F1 відкриває **висувне знизу меню Start**.
  Анімація і координати натискання використовують спільну геометрію.
- На стільниці є папки Documents / Pictures / Downloads / Program Files.
  Клік відкриває каталог у Files, drag-and-drop переставляє його значок.
  Базове дерево read-only, а блокнот має обмежений volatile RAMFS
  для запису текстових файлів у Documents.
- Праворуч угорі відображається час `HH:MM:SS RTC` із реально
  прочитаного CMOS годинника. Оновлюється незалежно від руху миші.
  **Не називаємо його київським часом**, доки немає достовірної
  конфігурації UTC/local-time й правил DST; RTC у VM може бути
  налаштований по-різному.
- Локація значків, тема, вибрана мова — наразі volatile.
  Перезавантаження скидає ці значення.

**Налаштування**

**Персоналізація (нове):** правий клік мишею на вільному місці робочого
столу відкриває контекстне меню із діями «Персоналізація» та
«Налаштування екрана». Перша відкриває Settings → Personalization, де
кліком можна перемикати вбудовані фони Ocean / Sunset / Forest,
акцент Teal / Violet / Amber та світлу/темну тему. Другий пункт
відкриває загальні Settings із фактичною роздільною здатністю GOP,
а **не** змінює відеорежим без драйвера.

- Меню відкривається тільки по **натисканню** правої кнопки на порожньому
  тлі; над вікнами, панеллю задач, ярликами та папками воно не з'являється.
- Лівий клік поза меню або Esc закриває меню. У Settings → Personalization
  Esc повертає до огляду Settings без закриття самого вікна.
- Картка «Персоналізація» в загальному Settings веде на ту саму сторінку.
- Шпалери — процедурні градієнти, не зображення з файлової системи.
- Усі зміни діють відразу лише в оперативній пам'яті; після перезавантаження
  параметри скидаються (сховища конфігурації поки немає).

**Personalization v2 (2026-11-07):**

- Три маленькі інтерактивні прев'ю шпалер та три палітри акценту
  дозволяють обрати варіант **без циклічного перегортання**. Клік по
  лівій частині існуючої картки й надалі перемикає значення по колу.
- Кнопки `SAVE RAM`, `LOAD RAM` і `RESET` у розділі персоналізації
  зберігають профіль до `Documents/THEME.TXT`, завантажують його або
  повертають Ocean / Teal / темну тему. У невеликих вікнах, де бракує
  місця, кнопки не показуються.
- `THEME.TXT` має текстовий формат `ZILLAOS-THEME/1` з полями
  `wallpaper`, `accent`, `theme`. Можна відкрити та редагувати
  через Zilla Notepad; невідомі поля, помилкова версія та пошкоджений
  UTF-8 відхиляються без зміни поточного оформлення.
- `SAVE RAM` не означає запис на фізичний диск: це лише обмежений
  Documents RAMFS (не більше 8 текстових файлів). Помилки місткості та
  формату показуються прямо на сторінці; перезавантаження обнуляє файл.
- Постійне збереження до SSD/HDD, PNG/JPG-декодер і імпорт власних
  шпалер поки що **не реалізовані**: для цього ще потрібні надійні
  VFS/драйвер накопичувача, введення файлів і обмежений декодер.


У Settings кліком на картці Appearance змінюється тема;
на картці Language — мова. Значення чинні для поточної сесії (RAM).
На екрані Display показано **фактичні** ширину та висоту framebuffer.

## Роздільна здатність: справжній вибір відеорежиму при старті

Доступні пункти меню Limine (після складання НОВОГО ISO):

1. ZillaOS — автоматичний відеорежим, за замовчуванням через 5 с.
2. ZillaOS 800x600.
3. ZillaOS 1024x768.
4. ZillaOS 1280x800.
5. ZillaOS 1600x900.
6. ZillaOS 1920x1080.

Вибір працює **до запуску ядра** через графічний режим UEFI/GOP,
а не через псевдомасштабування. Якщо VMware UEFI не пропонує
обраний режим, Limine сам вибирає доступний. Меню слід використати
при наступному ввімкненні VM.

У Settings показано пасивно виявлений PCI відеоадаптер. Якщо це VMware
SVGA II, система позначає його як **виявлений, але без активного
апаратного прискорення**. Докладно: [WINDOWS_GRAPHICS.md](WINDOWS_GRAPHICS.md).

**Зараз ZillaOS не вміє змінювати фізичну роздільну здатність
уже запущеної VM.** Режими понад 1280×800 використовують повільніший
CPU direct framebuffer, доки не буде готовий VMware SVGA драйвер. Для такого перемикача потрібно реалізувати
драйвер VMware SVGA / керування відеорежимами та безпечне
перевиділення framebuffer. Кнопка в Settings не повинна обіцяти
функцію, якої ще немає.

## Збірка у Windows

Перед оновленням ISO **повністю вимкнути** віртуальну машину,
щоб VMware не тримав відкритий файл диска.

```powershell
cd M:\projects\ZillaOs
git pull origin main
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows.ps1 -Action BuildRun
```

Результат: `M:\projects\ZillaOs\dist\ZillaOS-Desktop-UEFI.iso`.
Якщо VM вже створена, її VMX може використовувати той самий образ;
не створювати другу VM без потреби.

## Межі поточної реалізації

- Поки що всі вікна — вбудовані у ядро демо-представлення, без
  ізольованих користувацьких процесів.
- Files тепер переглядає **реальне для цього прототипу read-only дерево в пам'яті**: `/Program Files`, `/Users/Guest/Documents`, `/System`, `/Temp`. Папки відкриваються кліком, `Backspace` повертає назад, тестові `.TXT` можна переглядати. **Постійних файлів і запису на диск ще немає**. Деталі: [FILESYSTEM.md](FILESYSTEM.md).
- Terminal — демонстраційне вікно, а не повноцінна оболонка команд.
- Локаль і тема в RAM, після вимкнення VM не зберігаються.
- Розкладка клавіатури для введення тексту — базовий ASCII/PS2,
  навіть якщо мова інтерфейсу українська чи російська.
- У наявній збірці немає драйвера диска для звичайних файлових
  операцій або встановлення ОС на фізичний диск.

## Наступні технічні етапи повноцінного Desktop

1. **Драйвер дисплея та compositor**: runtime mode setting,
   повідомлення про зміну viewport, новий backbuffer, тест кліпінгу
   800×600…1920×1080, безпечна підтримка VM SVGA.
2. **Системні служби і процеси**: планувальник, кільця привілеїв,
   адресні простори, IPC, винесення застосунків із ядра.
3. **VFS + накопичувачі**: читання справжніх файлів,
   контроль прав і безпечний драйвер носіїв; лише потім запис.
4. **Реальний Terminal**: процес оболонки, потоки stdin/stdout,
   командний парсер, історія та робочий каталог.
5. **Повноцінна локалізація**: UTF-8 шрифти, IME та розкладки
   клавіатури, розділення UI locale й input locale,
   запам'ятовування мови та налаштувань.
6. **Session/Desktop manager**: справжні значки файлів,
   вікна незалежних програм, сповіщення, taskbar, Alt-Tab,
   меню, діалоги й збереження параметрів.

Критерій готовності кожного етапу — host unit tests, успішна
компіляція `x86_64-unknown-none`, запуск UEFI ISO у VMware/QEMU
і перевірка вводу/виводу без пошкодження реальних дисків.
